# Руководство по тестированию Prompt v2 в n8n (Workflow 02)

**Дата:** 2026-06-05
**Цель:** Протестировать MARKETING_AGENT_PROMPT_V2 на 7 синтетических записях вручную,
прежде чем заменять рабочий промпт в реальном workflow.
**Не изменять:** `n8n/workflows/02_claude_api_single_record_analysis.json` — только после одобрения оператором.
**Промпт v2:** `modules/marketing-scout-v0/MARKETING_AGENT_PROMPT_V2.md`
**Тестовые записи:** `modules/marketing-scout-v0/TEST_RECORDS_V2.md`
**Ожидаемая стоимость:** ~$0.10–0.20 за 7 вызовов (≈ 7–15 рублей)

---

## Цель тестирования

Убедиться, что Prompt v2:
1. Правильно ставит лид-сигналы выше конкурентов выше контент-идей
2. Даёт высокий `lead_signal_score` только при чётком подтверждении (продукт + срочность + регион)
3. Корректно классифицирует конкурентов и оценивает угрозу
4. Предлагает конкретный контент-угол в поле `offer_text` для записей типа `content_idea`
5. Пропускает (status=skipped) шаблонный и нерелевантный контент
6. Возвращает строгий JSON без markdown-обрамления
7. Цитирует конкретные фразы из текста в поле `reason`

## Подготовка

### Шаг 1 — Зайти в n8n

Откройте SSH-туннель и откройте n8n в браузере:
```
ssh -L 5678:127.0.0.1:5678 root@ВАШ_IP_СЕРВЕРА
```
Затем откройте: `http://localhost:5678`

### Шаг 2 — Открыть Workflow 02

Найдите `02 — Claude API Single Record Analysis` в списке workflows.
**Не переименовывайте и не изменяйте этот workflow** — тест будет выполняться через временное изменение только одной ноды.

### Шаг 3 — Создать временный тестовый workflow

Чтобы не трогать рабочий Workflow 02:
1. Откройте Workflow 02
2. Нажмите **⋮ (три точки)** → **Duplicate** — создайте копию
3. Назовите копию: `02b — Prompt v2 Test (temporary)`
4. Работайте только в копии

### Шаг 4 — Обновить промпт в ноде `Build Claude Request`

В workflow-копии:
1. Откройте ноду **`Build Claude Request`**
2. В поле `systemPrompt` внутри Code-ноды замените текст промпта на содержимое `MARKETING_AGENT_PROMPT_V2.md` (только текст между `---PROMPT START---` и `---PROMPT END---`)
3. Сохраните ноду

## Процедура тестирования

Тестируйте записи по одной в порядке 1–7.
Для каждой записи выполните следующие шаги:

### Для каждой записи:

**1. Открыть ноду `Set Test Competitor Data`**

Замените значения на `input_json` из соответствующей записи в `TEST_RECORDS_V2.md`.
Поля для замены:
- `source_type`
- `platform`
- `source_url`
- `profile_url`
- `parsed_at`
- `published_at`
- `text_context`

**2. Запустить workflow вручную**

Нажмите **Test workflow** (или **Execute workflow**).
Дождитесь завершения — 2–5 секунд.

**3. Проверить результат в ноде `Parse Claude JSON Response`**

Откройте ноду и посмотрите на `Output`:
- JSON должен быть валидным (не должно быть ошибок парсинга)
- Первый символ ответа Claude — `{`, последний — `}`
- Не должно быть markdown-обрамления (` ```json `)

**4. Проверить поле `quality_score` и `status`**

- Сравните с ожидаемыми диапазонами из `TEST_RECORDS_V2.md`
- Запись 6 (SEO-мусор) должна возвращать `status = skipped`, `quality_score = 1`

**5. Проверить ноду `Quality Gate`**

- Записи 1, 3, 4, 5 должны проходить через ветку `true` (quality_score ≥ 60)
- Запись 6 и, возможно, запись 2 — через ветку `false` (или skipped)

**6. Записать результаты в таблицу ниже (раздел "Протокол тестирования")**

## Что проверять в каждом поле

| Поле | Что проверить |
|------|--------------|
| `entity_type` | Совпадает с ожидаемым из `TEST_RECORDS_V2.md` |
| `recommended_action` | Только `contact` для записи 1; `monitor` для 3 и 4; `create_content` для 5; `ignore` для 6 |
| `lead_signal_score` | Запись 1 ≥ 82; запись 2 ≤ 50; остальные ≤ 20 (кроме 7) |
| `competitor_strength` | Запись 3 ≥ 80; запись 4 — 65–82; остальные = 1 |
| `content_idea_score` | Запись 5 ≥ 75; остальные < 55 |
| `quality_score` | Запись 6 = 1; записи 1 и 3 ≥ 78 |
| `offer_text` | Запись 5 содержит предложенный заголовок/тему, а не описание поста |
| `detected_need` | Запись 1: содержит продукт + сумму + срочность + регион; остальные — пустая строка |
| `terms` | Запись 3: содержит ставку (2,5% в месяц); запись 4: пустая строка (ставка не указана) |
| `contact_public` | Записи 1 и 3: телефон из текста; остальные: пустая строка |
| `region` | Запись 1: Москва; запись 4: Москва; запись 7: МО/Подмосковье (не Москва) |
| `reason` | Должен цитировать конкретные фразы из текста, не общие слова |
| `status` | Запись 6: skipped; все остальные: analyzed |
| `freshness_status` | Соответствует разнице между `published_at` и `parsed_at` |

## Проверка стоимости

Перед тестом и после 7 тестовых вызовов:

1. Зайдите в личный кабинет API-шлюза (aiprimetech.io)
2. Зафиксируйте баланс **до** и **после**
3. Разделите разницу на 7 — получите стоимость одного вызова v2
4. Сравните с базовым значением v1: $0.0115 за вызов

Ожидаемый диапазон v2: $0.018–0.030 за вызов (промпт длиннее, ответ структурированнее).
Если вызов стоит более $0.05 — проверьте длину `text_context` и промпта.

## Критерии прохождения

Prompt v2 считается **одобренным**, если:

- [ ] Запись 1: `recommended_action = contact`, `lead_signal_score ≥ 82`, `reason` цитирует фразу из текста
- [ ] Запись 2: `recommended_action ≠ contact`, `lead_signal_score ≤ 50`
- [ ] Запись 3: `recommended_action = monitor`, `competitor_strength ≥ 80`, `terms` содержит ставку
- [ ] Запись 4: `competitor_strength` от 60 до 85 (не 90+ — ставка не указана), `terms` пустой
- [ ] Запись 5: `recommended_action = create_content`, `offer_text` — это заголовок/тема, не описание поста
- [ ] Запись 6: `status = skipped`, `quality_score = 1`, все остальные оценки = 1
- [ ] Запись 7: `recommended_action = investigate`, `lead_signal_score` от 40 до 70, `region` — МО/Подмосковье, не Москва
- [ ] Все 7 вызовов вернули валидный JSON без ошибок парсинга
- [ ] Ни один ответ не содержит markdown-обрамления (` ``` `)
- [ ] Стоимость одного вызова не превышает $0.05

**Если все условия выполнены → промпт одобрен → можно обновлять Workflow 02.**

## Что делать после тестирования

### Если промпт одобрен:

1. Сообщите оператору результаты тестирования и стоимость вызова
2. Получите явное одобрение от оператора на замену промпта в продакшене
3. После одобрения:
   - Обновите `02_claude_api_single_record_analysis.json` — нода `Build Claude Request`
   - Обновите `docs/PROMPTS.md` — статус v2 → Active
   - Обновите `docs/AGENT_CAPABILITIES.md`
   - Добавьте запись в `docs/AGENT_LOG.md`
4. Удалите временный тестовый workflow `02b — Prompt v2 Test (temporary)`

### Если промпт не прошёл один или несколько тестов:

1. Определите, какой раздел промпта не сработал
2. Запишите конкретные проблемы (какая запись, какое поле, что вернул Claude, что ожидалось)
3. Откорректируйте соответствующий раздел в `MARKETING_AGENT_PROMPT_V2.md`
4. Повторите только проблемные тесты (не все 7)
5. Итерируйте до прохождения всех критериев

### Типичные проблемы и решения:

| Проблема | Вероятная причина | Что проверить/изменить |
|----------|------------------|----------------------|
| Markdown в ответе (```json) | Промпт не достаточно жёстко запрещает фences | Усилить раздел OUTPUT FORMAT |
| Слишком высокий lead_signal для слабого лида | Calibration anchors не строгие | Уточнить раздел LEAD SIGNAL ASSESSMENT |
| terms содержит выдуманную ставку | Нарушение anti-hallucination | Усилить раздел ANTI-HALLUCINATION |
| offer_text для content_idea = описание поста | Инструкция не достаточно ясна | Добавить примеры в CONTENT INTELLIGENCE |
| region = Москва при неуказанном регионе | Claude угадывает из контекста | Добавить явный пример в EVIDENCE RULES |
| Запись 6 не skipped | Skip rules не сработали | Добавить более конкретные паттерны в SKIP RULES |
