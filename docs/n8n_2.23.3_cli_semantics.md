# n8n 2.23.3 CLI semantics (QA-012 evidence)

Captured from the verified immutable image (`n8nio/n8n`, image id
`sha256:c0c39b1ca69d43f736bc65f8ddd70972a8989f736e8a4b6a075823f98cc48a23`, `n8n --version` → `2.23.3`,
bundled `node v24.15.0`) in a disposable, network-isolated container
(`docker run --rm --network none`). No production volume, no credentials, no activation/publication performed —
the semantics below are read from `--help`, not from mutating any workflow.

## Does a separate publish/unpublish CLI exist? — YES (this is new vs. legacy n8n)

`n8n --help` lists, verbatim:

```
publish:workflow:    Publish a specific version of a workflow. If no version is specified, publishes the current version.
unpublish:workflow:  Unpublish workflow(s)
update:workflow:     [DEPRECATED] Update workflows - use publish:workflow or unpublish:workflow instead
```

So legacy assumptions ("OSS n8n has no publish step; activation is only `update:workflow --active=true`") are **false
for 2.23.3**. `update:workflow` still works but is deprecated.

### `n8n update:workflow --help`
```
FLAGS
  --active <value>  Active state the workflow/s should be set to
  --all             Operate on all workflows
  --id <value>      The ID of the workflow to operate on
DESCRIPTION
  [DEPRECATED] Update workflows - use publish:workflow or unpublish:workflow instead
EXAMPLES
  $ n8n update:workflow --all --active=false
  $ n8n update:workflow --id=5 --active=true
```

### `n8n publish:workflow --help`
```
FLAGS
  --id <value>         The ID of the workflow to publish
  --versionId <value>  The version ID to publish. If not provided, publishes the current version
  --all                (Deprecated) This flag is no longer supported
```

### `n8n unpublish:workflow --help`
Exists; unpublishes workflow(s) (the rollback of `publish:workflow`).

## Imported publication/active state — SAFE BY DEFAULT

### `n8n import:workflow --help`
```
FLAGS
  -i, --input <value>  Input file name or directory if --separate is used
  --separate           Imports *.json files from directory provided by --input
  --activeState        Whether to respect the JSON active field. "false" (default) deactivates all imported
                       workflows. "fromJson" activates/deactivates each workflow based on its JSON active field.
```

**Key finding:** `import:workflow` defaults to `--activeState=false`, which **deactivates every imported workflow
regardless of its JSON `active` field**. Importing therefore cannot accidentally activate anything. Our deploy
passes `--activeState=false` explicitly so the safe behavior is pinned even if the default ever changes.

### `n8n list:workflow --help`
```
FLAGS
  --active <value>  Filters workflows by active status. Can be true or false
  --onlyId          Outputs workflow IDs only, one per line.
```

### `n8n export:workflow --help`
```
FLAGS
  --all / --id / --separate / --output / --pretty
  --backup       Sets --all --pretty --separate for simple backups.
  --published    Export the published/active version
```

## What `update:workflow --active=true` changes

It sets the workflow's `active` flag. On 2.23.3 the recommended equivalent is `publish:workflow --id=<id>`
(activate / publish the current version); the rollback is `unpublish:workflow --id=<id>`.

## Deploy behavior chosen (matches proven semantics)

* **Import** uses `n8n import:workflow --input=<file> --activeState=false` → every workflow lands inactive.
* **Activate** prefers the modern `n8n publish:workflow --id=<id>`; if the running CLI lacks it (older n8n) it
  falls back to the deprecated `n8n update:workflow --id=<id> --active=true`.
* **Deactivate / rollback** prefers `n8n unpublish:workflow --id=<id>`, falling back to
  `n8n update:workflow --id=<id> --active=false`.
* The deploy never publishes/activates a callable sub-workflow — only the trigger workflows (WF18 always; WF23
  if monitoring; WF25 if weekly digest).

## Safe rollback procedure

1. `scripts/deploy_n8n.sh --deactivate-triggers` → `unpublish:workflow` (or deprecated `--active=false`) for the
   exact trigger ids that were activated.
2. If a full rollback is needed, delete the imported workflows in the n8n UI (no destructive CLI delete is used by
   this repo).
3. Production is never mutated by any test/smoke in this repo; only operator-run `--apply` / `--activate-triggers`
   change a real instance.
